# 三个真实书源的模式分析

样例位置：`skills/BookSource_202609232645.json`。该文件是 UTF-8 JSON 数组，包含 3 个书源。只借鉴模式，不复制站点专属 token、选择器或许可受限内容；完整源的转载/二次开发须遵守其注释中的许可声明。

## 1. ESJ Zone：服务端 HTML + 默认/CSS 规则

特点：

- 搜索地址使用 `/tags-01/{{key}}/{{page}}.html`。
- `ruleSearch.bookList` 先选卡片容器，书名/作者/详情 URL 再相对抽取。
- 详情、目录、正文主要使用 CSS/默认规则；目录通过 `isVolume` 区分卷标。
- 启用登录页与 Cookie；发现页用静态分类 JSON，包含大量分类和分页 URL。

适用类比：传统服务端渲染小说站。先用声明式规则完成全链路，不要因为正文稍有清理需求就把所有规则改成 JS。

风险：位置索引、页面 class 改名、区域/IP/登录差异，以及发现分类过多导致维护成本高。

## 2. 轻之国度：JSON API + POST + Cookie 安全字段

特点：

- 搜索 URL 用 `@js:` 构造 POST JSON 请求，并从用户会话 Cookie 读取运行时安全字段。
- 发现规则先请求分类 API，再生成包含 POST 选项的发现数组。
- 搜索、发现、详情、目录和正文均围绕 JSON 响应；前置 JS 负责重组或保存中间 URL。
- 设置 Referer/User-Agent，并有登录状态检测。

适用类比：前端站点实际数据来自 JSON API，且请求体、Header 或 Cookie 中有动态字段。

风险：Cookie 不存在时 JSON 解析失败、API 参数变更、分页状态保存在源变量中、登录页成功但 API 会话仍失效。

## 3. 轻小说机翻机器人：API + 自定义登录 + `jsLib` + 多模式正文

特点：

- `searchUrl` 同时接受关键词和多个外部站点的作品 URL，并动态生成 API 地址。
- `loginUi` 定义账号/密码字段；登录 JS 获取 Bearer token 并存入 Legado 登录头。
- `jsLib` 提供复用函数；书源/书籍变量控制原文、不同译文、对照和注音模式。
- 目录 JS 把卷与章节统一成列表，并为章节计算 URL/时间。
- 正文 JS 根据变量选择不同段落集合并做格式化。

适用类比：聚合 API、需要自定义授权、同一书籍存在多种内容视图的书源。

风险：JS 过长、网络副作用隐藏在辅助函数、变量取值不合法、token 过期、第三方上游 ID 规则变化。

## 选择模式

| 目标站特征 | 首选模式 |
|---|---|
| HTML 中已有完整列表与正文 | ESJ 模式：默认/CSS 规则 |
| 页面只是壳，XHR 返回 JSON | 轻之国度模式：API + JSONPath，必要时构造 POST |
| 多上游、多内容模式、自定义授权 | 机翻机器人模式：API + 小型 JS 模块 |

## 反例

- 不要复制一个大段 `jsLib` 后只改域名。
- 不要把样例中的 User-Agent、Referer、Cookie 名或字段路径当成 Legado 固定要求。
- 不要把空 `ruleExplore` 误判为错误；先确认发现 URL 是否直接复用搜索结构。
- 不要从文件名推断更新时间；以源对象的 `lastUpdateTime` 和实际变更为准。
- 不要宣称某模式可跨版本工作，必须在用户目标版本中实测。
