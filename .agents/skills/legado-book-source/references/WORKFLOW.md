# 工作流与验收

## 1. 接收输入

尽量取得以下信息；缺少非关键项时先用合理默认值继续：

- 目标站首页、一个可搜索书名、一个详情页 URL、一个章节 URL。
- 需要的能力：搜索、发现、登录、正文分页、图片、音频、变量、自定义请求。
- 是否允许使用公开 API，是否需要用户自己的登录态。
- 目标 Legado/阅读版本及输出文件位置。

输出开始前写一张侦察表：

| 阶段 | 请求 URL/方法 | 输入变量 | 返回类型 | 列表/根节点 | 主键或稳定字段 |
|---|---|---|---|---|---|
| 搜索 |  | `key`, `page` | HTML/JSON |  |  |
| 详情 |  | `bookUrl` | HTML/JSON |  |  |
| 目录 |  | `tocUrl` | HTML/JSON |  |  |
| 正文 |  | `chapterUrl` | HTML/JSON |  |  |

## 2. 侦察网站

1. 先查看页面源代码，再看浏览器网络请求；不要只依赖渲染后的 DOM。
2. 判断数据来源：服务端 HTML、内嵌 JSON、XHR/fetch API、GraphQL、需执行脚本的页面。
3. 对每个阶段保存一个最小响应样本或字段说明，确认字符集、重定向与内容类型。
4. 记录分页规则：1 起始还是 0 起始、页码/游标、末页表现、空页表现。
5. 记录身份状态：Cookie、Authorization、Referer、CSRF、一次性签名。不得把真实密钥写入书源或报告。
6. 若站点有反爬、验证码或授权限制，停止绕过尝试，改为使用官方接口、用户授权会话，或明确报告限制。

## 3. 先完成最小垂直切片

按以下顺序实现并每步验证：

1. `bookSourceUrl` 与必要 `header`。
2. `searchUrl` + `ruleSearch`：用已知关键词至少返回一本书，且 `name`、`bookUrl` 正确。
3. `ruleBookInfo`：详情页名称、作者、封面、简介与 `tocUrl` 正确。
4. `ruleToc`：目录数量合理，章节名与章节 URL 一一对应。
5. `ruleContent`：正文非空、无导航/广告污染、段落顺序正确。
6. 再增加发现、登录、正文下一页、变量、卷标、图片/音频等能力。

不要一次写完整书源后再统一调试；这样很难判断错误发生在请求、列表切分还是字段抽取。

## 4. 规则设计原则

- HTML：优先 ID、语义 class、`data-*` 属性；避免依赖易变化的第 N 个节点。
- JSON：优先稳定键和 ID；列表规则先定位数组，再在当前元素内提取字段。
- 复杂逻辑：先声明式抽取，再用短 JavaScript 做转换。多处复用才放入 `jsLib`。
- 请求：URL 规则负责方法、请求体、请求头与动态地址；字段规则不要偷偷发无关请求。
- 状态：登录信息、Cookie、源变量、书籍变量分清作用域；敏感值只从运行时读取。
- 容错：仅在确有替代数据结构时使用 `||`；不要用宽泛选择器掩盖错误页面。

## 5. 调试矩阵

每个书源至少测试：

| 场景 | 通过条件 |
|---|---|
| JSON 语法 | 能被标准 JSON 解析器读取 |
| 搜索第 1 页 | 已知关键词返回预期书籍 |
| 搜索后续页 | 页码变化且结果不重复第一页 |
| 详情 | 名称/作者/封面/简介/目录地址正确 |
| 目录 | 数量合理；首章、末章 URL 可访问 |
| 正文 | 正文非空，段落顺序与换行合理 |
| 相对链接 | 书籍、封面、目录、章节 URL 均能正确补全 |
| 登录态 | 未登录提示明确；登录后不泄露 token |
| 异常页 | 404、空结果、会话过期不会被当成正文 |

若可运行 Legado，使用书源编辑器按“搜索 → 详情 → 目录 → 正文”逐级调试。若无法运行，明确写出“仅完成静态验证”，不要宣称已导入成功。

## 6. 故障定位

- 搜索为空：先检查请求方法/编码/分页，再检查 `bookList`，最后检查字段规则。
- 字段全相同：多半未在列表元素上下文中取值，或误用了绝对规则。
- URL 打不开：检查相对 URL、协议、转义、重定向和字段是否抽到了标题而非 href。
- 目录为空：确认详情规则生成的 `tocUrl`，再检查目录响应是否需要登录或二次 API 请求。
- 正文是错误页：检查 Cookie/token、Referer、章节 ID、响应状态和登录失效文本。
- JavaScript 返回空：分别打印/检查输入 `result`、中间对象和最终表达式；不要吞掉异常。
- 导入失败：先运行验证器，再排查 JSON 字符串中的反斜杠、引号和实际换行。

## 7. 交付格式

交付时列出：

1. 生成/修改的 JSON 绝对路径。
2. 支持与未支持的能力。
3. 已验证的书名、页面和测试阶段；敏感数据必须脱敏。
4. 使用了哪些选择器/API 及其稳定性假设。
5. 需要用户在 Legado 中完成的登录、验证码或版本确认步骤。
